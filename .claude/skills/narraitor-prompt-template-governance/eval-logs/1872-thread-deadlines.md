## Round 8, declared before the code (2026-08-18): reconciliation on OPEN

The memo's re-entry item 1, and only that. Structural, not wording: the extraction contract and the store change; the scene block, `selectDueNowThread`, the seam and the flag do not.

1. Extraction contract: every `opened` entry may carry `covers`, the id of an open thread that this arrival, message, sound or move is landing or moving; null (or absent) when nothing open covers it. The JSON skeleton shows the field. The parser keeps it as-is (fail-open: a missing or unknown value opens as before).
2. Store routing: an opened entry whose `covers` names one of this session's open threads does not create a thread. It refines that thread: the summary becomes the specific event the model just named ("Mr. Henderson comes to collect the roof loan", not "those who appointed you will seek repayment"), the kind follows the entry, `dueByTurn` is re-filed from the entry when given (floored at the horizon as before) and kept otherwise, `lastAdvancedAtTurn` moves, and the old summary is kept in `notes` as `<new> (was: <old>)`. It counts as an advance in the segment stamp. A `covers` that points at a resolved or foreign thread opens a new thread, as today.
3. Extraction prompt: the thread list marks each overdue thread with "OVERDUE by N turns" and the one the scene block asked to land with "DUE NOW: this segment was asked to land it", computed by `applyWorldClockUpdates` from the same store state and turn index the block used (`dueNowThreadId` on the extraction input). The OPEN rule says to check the list first, the DUE NOW thread first, and to file a match under `covers` instead of as new.

Why this and not more: round 7's nine threads were the seed's favors thread landing three times under three names; with the specific event replacing the vague one and its due re-filed, the DUE NOW pick clears by arithmetic when the model gives the arrival a timescale, and the ledger stays at the number of pressures the story actually has. Item 2 (a fired state rendered to the scene block as "already in the room") is NOT in this round; if re-announcement survives reconciliation it is the next round.

## Round 9, declared before the code (2026-08-19): a fired state

1. Store: `WorldThread.firedAtTurn` (optional turn index). Set by `applyExtraction` when (a) an opened entry `covers` the thread (the arrival is what just happened), or (b) an advance lands on the thread that is the DUE NOW pick this turn (the pick recomputed from the pre-update open threads with the same `selectDueNowThread`; the block told the segment to land it and the extractor recorded a real change, so it fired). Nothing else sets it; nothing clears it short of resolution.
2. Pick rule: `selectDueNowThread` skips fired threads. A fired thread is still open, still ages, is still counted overdue and still sits in the "MUST advance at least one" set; it is never again the thread the block demands an arrival for.
3. Scene block: a fired thread renders `[IN THE SCENE since turn N: <its last recorded move>]` instead of a DUE NOW or overdue mark, and the standing rules gain one line: an IN THE SCENE thread has already arrived; never arrive it again or deliver it as news; what it owes now is its next move, its cost, or its outcome. When every open thread is fired and nothing is DUE NOW, the spend rule adds the empty-ledger ask (one new pressure from off-stage that becomes a thread the story owes), because nothing on the ledger is left to arrive. `WorldClockPromptContext.threads[i]` gains `fired` and `lastMove` (the last note, model-written prose, no ids).
4. Extraction: the thread line marks `IN THE SCENE since turn N`, and the OPEN rule says an actor already in the scene is not a new thread: their next move is an ADVANCE, their outcome a RESOLVE.
5. Observability, no behavior: `logger.warn` on the goal-extraction parse-failure branch so a missing stamp can be attributed; the audit script counts opens per session and fired threads.
